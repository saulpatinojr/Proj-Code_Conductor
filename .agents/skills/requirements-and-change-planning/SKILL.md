# Requirements and Change Planning

Restate the desired outcome and distinguish business requirements, technical constraints, repository facts, assumptions, recommendations, and questions. Define in-scope and out-of-scope items, acceptance criteria, non-functional requirements, affected owners, dependencies, data or trust boundaries, and approval gates.

Compare only options that could reasonably satisfy the goal. Explain trade-offs in maintainability, operability, security, performance, cost, compatibility, reversibility, and team cognitive load. Choose a default when evidence supports one; hold open only a true blocker.

Plan implementation, tests, telemetry, migration, rollout, rollback, documentation, and follow-up. Use `handoff-template.md` for specialist work and `adr-template.md` for consequential decisions.
