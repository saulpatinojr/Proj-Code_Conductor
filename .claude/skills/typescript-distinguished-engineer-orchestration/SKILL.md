# Distinguished Engineer Orchestration

Use when the task crosses components, has ambiguous requirements, or needs implementation plus review. Establish repository identity, governing instructions, requested outcome, acceptance criteria, affected systems, trust boundaries, and authorization. Inspect before choosing a framework or adding a dependency.

Maintain a fact/assumption/decision/blocker ledger. Prefer the smallest coherent change and existing patterns. Use specialists only when independent security, testing, or evaluation work is valuable; provide the handoff fields in the installed `typescript-distinguished-engineer-contract` instruction.

Before claiming completion, compare every acceptance criterion with evidence, inspect the diff, report checks and skipped checks, state security/operations/cost impact, and select one completion status from the primary agent contract. Keep external mutations approval-gated.
