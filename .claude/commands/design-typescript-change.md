# Design a Change

Restate the goal. Inspect repository instructions, architecture, manifests, tests, CI, and affected code. List verified facts, assumptions, constraints, trust boundaries, data sensitivity, and unknowns. Define acceptance criteria and in/out of scope. Compare viable options, select a recommendation, and explain maintainability, operability, security, compatibility, performance, cost, reversibility, and ownership trade-offs. Include implementation slices, tests, telemetry, migration, rollback, approval needs, and ADR needs. Do not edit until the requested planning gate is satisfied.
