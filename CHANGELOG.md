# Changelog

All notable Code Conductor changes are recorded here. The project follows a pre-1.0 development model; entries remain under **Unreleased** until a release/tag is created.

## Unreleased

### Added

- Repository governance (#3): APM audit and npm lockfile validation now report on every pull request, so they can be required checks; their checkouts no longer keep credentials. `docs/REPOSITORY-GOVERNANCE.md` lists the exact required check names and the owner's ruleset, tag-ruleset, security and Actions settings, with a read-back command.
- Release engineering (#14; D-067): a Release workflow builds a draft GitHub release from a version tag on `main`. It uses three least-privilege jobs. The first tests and packages the `.vsix`, smoke-tests it installed, and writes a CycloneDX SBOM (checked against the bundled packages) and `SHA256SUMS`, without signing access. The second signs build provenance. The third verifies the attestation against the Release workflow, tag and commit (`gh attestation verify --cert-identity --source-ref --source-digest`), and confirms the tag has not moved before drafting the release. `docs/RELEASE.md` covers cutting, verifying, versioning, rollback, deprecation and the owner's Marketplace setup. `@types/vscode` now matches `engines.vscode` (1.105), and vsce's check for that runs again; workspace packages are private.
- VS Code-centered Code Conductor architecture and repository constitution.
- Vendor-neutral task, assignment, evidence, finding, gate, review, merge, and run-manifest contracts.
- Policy/risk validation, task planning, bounded execution, structured run persistence, and Git worktree support.
- Initial official-client adapters and workstation trust/smoke-test framework for Codex, Claude Code, Kiro, and Google Antigravity boundaries.
- GitHub Gatekeeper helpers for authentication, PR creation/status, and check inspection.
- APM 0.30.0 manifest, lockfile, policy, canonical agent/skill source, and materialized Copilot/Claude/Codex/Kiro/Agent Skills projections.
- Official MCP catalog/configuration foundation.
- First-party context optimizer package, CLI diagnostics/preparation commands, optional experimental MCP adapter, and VS Code estimated-savings telemetry.
- Thin VS Code extension foundation with Team, Runs, Gates, Connections, Packs, and Usage views.
- CI for TypeScript validation, tests, repository-policy validation, APM audit, dependency audit, lockfile consistency, CodeQL, and dependency review.
- Repository-specific GitHub Copilot code-review skill plus minimal repository-scoped `.github/mcp.json` for compatible Copilot CLI workflows.
- Repository governance documentation, contribution/security/review policies, templates, CODEOWNERS, Dependabot, EditorConfig, and Git attributes.
- Regression coverage for deep recursive gate-profile discovery, owner-only worktree directories, invalid structured agent-result payloads, configured role authority projection, independent-provider challenger enforcement, missing GitHub/APM/Git CLI diagnostics, ref-safe task/agent identifiers, rename-aware sensitive-path handling, evidence-store path traversal prevention, no-scan exact-file gate detection, context workspace boundaries, symlink escapes, sensitive/oversized context files, and first-party MCP provenance policy.

- `ccon agents` command and a `ccon doctor` summary providing a read-only provider-native agent/skill inventory across Claude, Copilot, Codex, Kiro, and Agent Skills locations at project and user scope, marked against `apm.lock.yaml` (ADR 0011).
- `ccon import <run-manifest.json>` validates an external `RunManifest` (for example from Code Workflow's `export`) and stores it in the private run store as `import-<runId>`; manifests carrying a `mergeDecision` or a `ready` recommendation are rejected (ADR 0011).
- Optional `AgentResult.notVerified` contract field; agents are instructed to declare checks they did not or could not verify, and malformed values fail closed (ADR 0011).
- Native interfaces (C03, #45; D-060): `ccon next` and the VS Code Runs view show each run's next native step. Steps include reviewing the agent worktree in Source Control, re-running interactively to approve, validating a harness, completing an assignment manually, fixing gates or findings, or opening a draft pull request yourself. Commands are shown or copied, never run. `ccon handoff` prints the exact prompt for a manual run. `RunManifest.worktrees` records agent worktrees. `ccon doctor` and the Connections view show the official sign-in command and documentation link per client.
- Local discovery and selective context (I10, #42; ADR 0007): context files are read through one descriptor opened without following symlinks. The kernel's path for that descriptor must be exactly the checked path, so a directory swapped for a symlink mid-read is refused, and hard-linked files are refused (a hard link can make a file from outside the workspace appear inside it). Only Linux (including WSL) exposes a descriptor's path to Node, so `ccon compress <file>` and the MCP `read_compressed_file` tool refuse to read files on macOS and Windows, before touching the path. A path that does not exist and one outside the roots get the same error, and every failed or redirected open gets one other error, so no single answer reveals whether a file exists elsewhere on the machine. A caller that can also rename folders in the workspace can still estimate it statistically over about a hundred reads; ADR 0007 records that residual. Startup keeps restoring fingerprinted, non-secret discovery without starting providers, ACP, MCP or APM.
- VS Code distribution (I01, #33; D-066): the `.vsix` now ships only the two bundles, the defaults, the schema, the icon and the docs, named by a `files` allowlist in the extension manifest; it no longer carries `tsconfig.tsbuildinfo`, per-file build output or declarations, nor stray files left in `apps/vscode`. Release preflight unpacks the package outside the checkout and runs it against an unrelated folder. Commands the extension copies name its bundled runtime instead of a `ccon` that is not on `PATH`, and a command is not offered when a value would not reach the program exactly: PowerShell's stop-parsing token `--%` on any platform, and, for PowerShell, an empty argument, an embedded double quote or a spaced argument ending in a backslash. `docs/INSTALL.md` covers prerequisites, compatibility, install, update and uninstall.
- Client states (I02, #34; D-065): a provider starts only when its official client reports a sign-in (`claude auth status`, `codex login status`, `kiro-cli whoami`) and, for subscription assignments, a subscription sign-in. Workstation trust is bound to the smoke-tested client version; an unreadable version is never trusted. `ccon doctor` reports installed, signed in, healthy and trusted separately. Status probes run with no prompt or repository, and keep no personal fields or key fragments. Claude Code runs with `--setting-sources user`, so a repository's Claude Code settings (`env`, `apiKeyHelper`, hooks) and `.mcp.json` cannot switch a subscription run to another credential or endpoint. The probes and the launch run the same client file from an absolute PATH entry, and both read the same configuration: relative `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `HOME` and `USERPROFILE` values are made absolute, empty ones are removed (Claude Code reads an empty `CLAUDE_CONFIG_DIR` as the working directory), and relative `ANTHROPIC_CONFIG_DIR` and XDG base directories are removed. A provider whose explicit configuration directory lies inside the repository (decided by file identity, so symlinks and case or spelling variants count) is not started, and `ccon harness-smoke` refuses it too. Results are read only from the client's final message.
- GitHub integration (I03, #35; D-064): `ccon github-gate` summarizes a pull request's native state (checks, reviews, stale approvals, merge state) read-only and is green only when every signal is. `ccon pr` previews the draft pull request for a run's agent branch. With `--create` it refuses sensitive or credential-bearing history (content or names), a remote that does not push to exactly one URL in the pull request's repository, and a base not yet on the remote. It asks for an approval bound to the exact push URL and text, with agent-reported credentials redacted and agent text rendered inert, then pushes that exact commit and nothing else (no tags or submodules, HTTPS or SSH only) without force or hooks using your Git credentials, and opens a draft with `gh`. It never merges or approves. `ccon github-gate` no longer passes `UNSTABLE` merge state or an unreported draft state. Repositories nested in an agent worktree are control state: one appearing stops a run, `ccon worktrees` keeps the worktree, and no Code Conductor Git command enters it. `git` and `gh` are run from absolute PATH entries only.
- Handoff packets (I05, #37; D-063): dependent assignments get a versioned packet with recipient, 24-hour expiry, authorised context, committed changes, `notVerified`, risks, prior findings, unresolved readiness disagreements and provenance. The packet is rendered into the prompt as claims to verify, stored owner-private, and digest-verified on read. `ccon handoff --json` prints it and refuses expired or altered packets. `ccon runs [--older-than <days> [--apply]]` lists and prunes local run evidence, keeping runs whose worktrees still exist. Packets are built only after the Git-control check passed, carry only what earlier agents' dependencies produced (committed files, not read-only claims), redact credential-looking strings, and render as a closed, JSON-quoted block that earlier agents cannot break out of; the disclosure approval names the packet. Imported manifests cannot carry handoffs.
- Agent worktrees (I04, #36; D-062): `ccon worktrees` lists recorded agent worktrees, and `--remove-clean` removes only clean ones while keeping their branches. Clean means content-exact, on the worktree's own `cc/` branch and under the Code Conductor root. `--cleanup-worktrees` applies the same rule, no longer throws on a kept worktree or hides the run outcome, and never prunes other worktrees. Neither runs Git in the worktrees of a run that stopped for a Git configuration change; gate commands that change Git configuration now stop the run too. Commits refuse new credential-looking strings and unscanned content, reported by location and kind only. Agent-made history is scanned blob by blob with no commit-count limit. Provider clients no longer receive separately billed API credentials, provider-selection variables (Bedrock, Vertex, Foundry, base URL, profiles, federation) or Git's repository-local variables; `KIRO_API_KEY` draws on subscription credits and is kept. A relative `CODE_CONDUCTOR_HOME` is resolved to an absolute path. Tests run with hermetic Git configuration.
- Declarative gate profiles (I06, #38; D-061): gates declare prerequisites (tool on `PATH`, installed dependencies) and fail closed without executing when they are missing; Code Conductor never installs them. New `pnpm` and `yarn` profiles take precedence over `node` via their lockfiles. `terraform validate` requires an initialised directory, and an explicit, advisory `terraform-plan` profile is never auto-detected. `ccon run --gate-profiles` chooses profiles for a run. Gate commands run in an isolated process group, reaped on exit and interruption, with timeout and 4 MiB output bounds; leftovers are terminated and a descendant holding the pipes cannot hang the run. Tools resolve from absolute `PATH` entries only, and that exact file runs and is shown in the approval. Advisory gates alone never establish readiness, and a missing prerequisite always blocks. Terraform/OpenTofu gates are limited to fmt/validate/plan (without `-out`)/version, and shells and command wrappers are rejected. The `terraform-plan` approval discloses that planning runs provider plugins and configuration-defined programs with your credentials. Gate evidence `sha256` covers the full untruncated output.
- Pre-action approvals (C02, #44; ADR 0013): `ccon run --execute` asks in the terminal immediately before starting a provider, disclosing context to it, running gate commands and committing. Each approval is bound by SHA-256 digest to the recipient, revision, working-tree content, prompt digest, exact gate command plan or exact commit tree; missing, denied, expired and changed-context approvals are refused and the run becomes `human_required`. Non-interactive runs cannot approve; the terminal prompt requires a request-derived confirmation code, so pre-typed input cannot answer it. Every retry is approved separately. `RunManifest.approvals` records non-secret evidence; `ccon import` rejects manifests carrying approvals. Denied commits leave changes uncommitted in the agent worktree.
- Code Conductor's own Git operations (agent commits, worktree creation, status/diff) never run repository hooks or a configured `core.fsmonitor` and ignore replace refs. Approved commits are created from the approved tree object (`git commit-tree` plus a compare-and-swap `update-ref`) under Code Conductor's own identity. Provider runs that change Git configuration or history files stop the run before any further Git operation. Commits an agent makes itself are named, their whole history is checked for sensitive paths, and they make the run `human_required`. Provider clients that ignore `SIGTERM` after a timeout are killed.
- Packaged configuration defaults (C01, #43): the seven canonical `config/*.yaml` documents ship with the policy package and VS Code distribution under a SHA-256 manifest; planner, gates, MCP, CLI and native views read them, so an unrelated workspace needs no Code Conductor source, config directory or APM scaffold.
- Bounded, schema-validated user (`~/.code-conductor/config.json`) and workspace (`.code-conductor/config.json`) preference overlays that can only reorder/narrow eligible harnesses or disable them; they cannot change risk roles, authority, independence, commands, MCP trust or billing. Symlinked, dangling, oversized or malformed overrides fail closed.
- `ccon workspace-validate <folder>` reports packaged/overlay provenance for an arbitrary workspace; `ccon validate` remains the strict source-repository check.
- Standalone bundle smoke test that runs the distributed CLI with only its packaged defaults/schema in an empty unrelated directory.
- ADR 0011 (Accepted) locking the Code Workflow sibling boundary and shared result contract, and ADR 0012 (Proposed) for provider-local subagent evidence hooks.

- Next actions treat run records as untrusted: `ccon next`, `ccon handoff` and the VS Code views show each value on one line with control and format characters replaced. Commands are quoted for the shell you paste into (POSIX or PowerShell), and a command is left out when a value cannot be shown exactly. A refused commit points to native review of the kept changes. A run stopped for a Git configuration change offers only a configuration check. Worktree paths are resolved through symlinks before review, and `ccon import` rejects worktree records. The extension shows a command before copying it.

### Changed

- The command-line interface is now `ccon` (D-068, ADR 0014), because `cc` is the C compiler on most POSIX systems. The bundled runtime is `dist/ccon.js`, and the npm scripts are `ccon:validate`, `ccon:doctor` and `ccon:plan`. Agent branches keep the `cc/` namespace.
- Selective MCP (I08, #40): `ccon mcp` states that it only selects servers by profile; Code Conductor starts none and grants no authority, and each native client activates and authorizes its own. For every server it shows provenance, maturity, source, default access and separate billing, and, where the catalog records them, the transport and the exact endpoint, endpoint template or pinned launch command. The context optimizer's experimental MCP transport leaves the packaged catalog until W-006, because its server exists only in a source checkout; `ccon compress <file>` remains the supported path (Linux and WSL; ADR 0007). The upgrade from manual Perplexity Pro research to the separately billed API is documented (#17): your own key, an explicit `--allow-api`, and configuration in your native client. No repository policy key enables it.
- Workstation runbook (#4, #9): `docs/WORKSTATION-VALIDATION.md` now starts from the verified release `.vsix`. It runs `ccon` through the extension's bundled runtime, measures startup with VS Code's Show Running Extensions (with an initial budget and a process check), takes the R2 scenario through `ccon pr` and `ccon github-gate`, and keeps a non-secret evidence checklist. The v0.1 release gate in `docs/IMPLEMENTATION-PLAN.md` now matches the zero-scaffolding scope (#32): no files are created in customer repositories, and APM is optional.
- Gate selection fails closed: an unrelated workspace with no applicable profile yields a blocking `no-applicable-gates` result instead of an empty (vacuously passing) gate set; the source-specific gate profile requires the exact `@code-conductor/root` package name.
- VS Code startup fingerprints include bounded user-level preferences so a changed user override is not served from a warm cache.
- Packaged defaults are regenerated by Vitest global setup, so watch mode and IDE test runners no longer need a separate `defaults:package` step (a TypeScript build is still required). Tests run with an isolated empty home directory so contributor preferences cannot change planning under test.
- `ccon doctor` validates all seven packaged configuration documents and points the Code Conductor source repository at the strict `ccon validate .` check.
- Deterministic gate evidence now records `sha256` over the full untruncated gate output.
- Refreshed `fast-uri` (3.1.8) and `source-map-js` (1.2.2) in the npm lockfile to clear new moderate/high advisories reported by `npm audit --audit-level=high`.
- `code-conductor-protocol` skill now asks agents to list unverified checks in `notVerified`; projections and `apm.lock.yaml` were re-materialized with APM 0.30.0.
- Upgraded Vitest to 5.0.0 and refreshed the committed npm lockfile.
- Standardized ongoing workflow names and removed temporary/bootstrap write-back workflows after their one-time use.
- Pinned maintained GitHub Actions to reviewed immutable commit SHAs.
- CodeQL and Release preflight now finish on every push to `main`; only a pull request's superseded run is cancelled. Both used one concurrency group per branch, so merges in quick succession cancelled the earlier commits' runs.
- The npm lockfile records the exact `zod` 4.6.7 pin that `packages/adapters` declares, so the npm lockfile check passes again.
- Pinned executable Ansible and Azure MCP npm package references instead of resolving floating versions at runtime.
- Reworked deterministic gate glob matching and expanded recursive-pattern regression coverage.
- Removed the former gate-profile directory-depth cutoff so recursive technology detection cannot silently skip deeply nested files.
- Gate-profile discovery now scans repository files lazily only when a configured profile requires `any_glob` matching.
- Corrected MCP profile detection so GitHub tooling is selected only for repositories with a Git marker.
- Preserved advisory deterministic-gate semantics through final readiness evaluation.
- Planner assignments now carry all configured role authorities, including execute-validation, disagreement-resolution, merge-recommendation, approval, and merge capabilities while retaining separation-of-duties policy.
- Planner availability and billing behavior are derived from harness automation configuration rather than hard-coded harness IDs.
- Challenger different-provider independence is enforced from the configured role threshold and fails closed when it cannot be satisfied.
- GitHub and APM subprocess diagnostics include spawn errors when their official CLIs are missing or cannot execute; Git helper startup failures are likewise explicit.
- Git worktree branch components are sanitized against invalid ref forms including repeated dots, leading/trailing dots, and `.lock` suffixes.
- Git status parsing uses NUL-delimited porcelain output and returns the destination/current path for rename and copy entries.
- Evidence run-directory names no longer admit path traversal semantics; unsafe external IDs are normalized and digest-suffixed.
- Context optimization now defaults to lossless/conservative preparation; comment/whitespace removal requires explicit aggressive mode, JSON compaction remains semantically safe, provider-specific cache-control markup was removed, and local token metrics are explicitly estimates.
- Context-optimizer MCP catalog metadata now distinguishes Code Conductor first-party experimental adapters from vendor-official servers.
- Replaced the unsupported duplicate `.github/copilot-mcp.json` approach with minimal `.github/mcp.json`; removed the transplanted Copilot setup/token-minter workflow that referenced infrastructure and secrets not owned by this repository.
- Reconciled Phase 1 tracking: issue #2 is complete and live workstation/R1/R2 validation is tracked in issue #4.
- Renamed the canonical repository to `saulpatinojr/Proj-Code_Conductor` and the APM package to `proj-code-conductor`; in-tree clone, issue-template, VS Code packaging, and repository-layout references now use the new name. See ADR 0010 and D-001.

### Security

- Handoff disclosure summaries count redaction markers with an exact string search instead of a regular expression whose worst case is quadratic (CodeQL `js/polynomial-redos`). The serialized packet always puts a closing bracket after agent-written text, so the old count was already linear in practice; the count no longer depends on that layout.
- Subscription-first billing policy and detection of API-key environment variables that could bypass intended billing paths.
- Fail-closed structured agent-result parsing and explicit workstation trust before unattended CLI execution.
- Structured `AgentResult` payloads are validated against the canonical JSON Schema before runtime acceptance.
- Human approval boundary for high-risk/destructive external operations.
- Local run/evidence, workstation-trust, modifying worktree, and context-optimizer telemetry directories/files use owner-only permissions on POSIX systems where applicable.
- Context file reads are bounded to configured workspace roots after canonical/symlink resolution and reject sensitive/state paths, non-regular files, and oversized inputs.
- Evidence-store path traversal and rename-based sensitive-file detection are covered by regression tests.
- Added high/critical dependency audit as a CI gate; the current dependency graph reports zero known npm vulnerabilities.
- Multiple GitHub Copilot Gatekeeper review rounds were exercised and concrete findings were addressed with targeted regression coverage.
- The runtime test suite no longer commits a contributor's uncommitted work. Its worktree double returned the checkout running the suite as the builder's worktree, so `npm test` with uncommitted changes committed them onto the current branch under the Code Conductor identity, bounded only by the sensitive-path denylist. The tests now use real linked worktrees of a throwaway repository. As defense in depth, `commitAgentChanges` refuses any checkout other than the agent's own worktree. The worktree must pass all of these checks:
  - It is the top level of a linked worktree, not a primary working tree.
  - It has the handle's `cc/` agent branch checked out.
  - Git can report the worktree layout. The check fails closed when it cannot, as with Git older than 2.31.

  Git subprocesses, and the test suite, also drop Git's repository-local environment variables (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and the rest of `git rev-parse --local-env-vars`). Otherwise, a run launched from a git hook or a dotfiles shell could be redirected onto a person's own checkout or index. Fixes #48.
- Gate shapes: a `node` gate script under a folder whose name ends in a dot is refused, because Windows drops the dot and `node_modules.` can name `node_modules` there. A malformed gate catalog is reported by `ccon validate` as `gates.catalog` instead of crashing it or passing. That covers an empty file, `profiles` or a profile that is not a mapping, a profile without a `gates` list (such as one written as its gates list, which also hid its commands from the gate checks), and a gate that is not a mapping.
