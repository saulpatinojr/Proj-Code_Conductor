# Code Conductor Decision Register

This file is the durable record of user-approved architectural decisions. It exists so the project does not depend on chat history or model memory.

## Status vocabulary

- **LOCKED**: approved baseline; change only through an ADR with evidence.
- **VALIDATE**: intended decision that still requires local/runtime verification before merge.
- **OPEN**: implementation detail not yet locked.

| D-059 | Consequential actions require a human decision immediately before the action, bound by SHA-256 digest to its exact context: provider start and context disclosure (per recipient, prompt digest, revision and working-tree content), deterministic gate commands (exact command plan), commits (exact tree) and deployments. | D-060 | Native interfaces first: Code Conductor presents next actions, scope and evidence and links to the native owner. Manual handoff prints the exact prompt for a person-driven run. See `docs/NATIVE-INTERFACES.md`. | LOCKED |
| D-061 | Deterministic gate profiles are packaged, detected from repository markers or chosen per run (`--gate-profiles`). They declare prerequisites; a missing tool or uninstalled dependencies is a blocking failure with nothing executed, advisory gates included, and Code Conductor never installs prerequisites. Advisory gates alone never establish readiness. Tools resolve from absolute `PATH` entries only, and that exact file runs and is bound by the approval. Gates run without a shell in an isolated process group, reaped on exit and interruption, with timeout and output bounds; leftovers are terminated. Terraform validation is separate from explicit, advisory plan review. Planning runs provider plugins and configuration-defined programs with the person's credentials, and the approval says so. Terraform/OpenTofu gates may only use fmt, validate, plan (without `-out`) or version. Shells, command wrappers and auto-approve flags are rejected by policy validation and the planner. See `docs/GATE-PROFILES.md`. | LOCKED |
| D-062 | Agent worktrees are isolated linked worktrees on `cc/` branches and are kept by default. Explicit cleanup (`cc worktrees --remove-clean`, `cc run --cleanup-worktrees`) applies one rule: it removes only a worktree under the Code Conductor root that has exactly its own `cc/` branch checked out and whose content matches that branch's head. Branches are kept, other worktrees are never pruned, and no Git runs in the worktrees of a run that stopped for a Git configuration change or has no outcome yet. Repositories nested in a work tree are control state: one appearing or changing stops a run, and a worktree holding one is never checked or removed; `git` comes from absolute PATH entries only. Other worktrees are retained and reported, and cleanup never hides a run's outcome. Commits refuse sensitive paths, new credential-looking strings and content past the scan budget before approval, reported by location and kind only; agent-made history is scanned blob by blob. Provider clients do not receive separately billed API credentials, provider-selection variables or Git's repository-local variables. See `docs/WORKTREES.md`. | LOCKED |
| D-063 | Dependent assignments receive a versioned, expiring handoff packet scoped to one recipient. The packet is built only after the Git-control check passed, redacts credential-looking strings, and is rendered into the prompt as a closed, JSON-quoted block of claims to verify (not evidence or instructions), so disclosure approval binds it and names it. It is stored owner-private with the run and verified by SHA-256 on read, and expired or altered packets are refused. Run evidence stays local with explicit retention (`cc runs --older-than --apply`). There is no central session database. See `docs/HANDOFFS.md`. | LOCKED |
| D-064 | GitHub integration goes through the official clients only. `cc github-gate` reads pull-request state via `gh pr view --json` and is ready only when every native signal is green; missing data never passes. `cc pr` previews by default. `--create` refuses branches whose history touches sensitive paths or adds credential-looking strings (in content or names), remotes that do not push to exactly one URL naming the pull request's repository, and bases not yet on the remote. It then asks for a `context_disclosure` approval bound to the exact head commit, push URL, title and body; agent text in the body is redacted and rendered inert. Only then does it push that commit and nothing else (no tags or submodules, HTTPS or SSH only) without force or hooks, and open a draft with `gh pr create --draft`, accepted only with a pull request URL in that repository. `git` and `gh` come from absolute PATH entries only. Code Conductor never merges, approves or stores GitHub credentials. See docs/GITHUB.md. | LOCKED |
| D-065 | Before a provider starts, Code Conductor asks its official client for its sign-in state (`claude auth status`, `codex login status`, `kiro-cli whoami`), run with no prompt or repository in an empty private directory and the provider environment. | D-067 | Releases come only from a `vMAJOR.MINOR.PATCH` tag on `main` that matches the extension version. The Release workflow runs three least-privilege jobs. | D-068 | The command-line interface is `ccon`, not `cc`: on most POSIX systems `cc` is the C compiler, so the old name could shadow it on `PATH` and made copied commands ambiguous. The bundled runtime is `dist/ccon.js`, and the repository's npm scripts are `ccon:validate`, `ccon:doctor` and `ccon:plan`. Agent branches keep their `cc/` namespace, so existing worktrees are still recognised. There is no `cc` alias, because the CLI was never published. See ADR 0014. | LOCKED |
| D-069 | The PowerShell gate profile is deferred until a repository Code Conductor works on needs one (#15). | D-070 | Context files are read only on Linux, including WSL and remote Linux hosts. Node exposes the kernel's path for an open descriptor only through `/proc/self/fd`, and the owner does not accept the check-then-open race on other platforms (ADR 0007, decision 4). Revisit only with a descriptor-bound location check for that platform. | LOCKED |
| D-071 | Every deterministic gate's full output is stored owner-private with the run (`runs/<runId>/tool-output/`), its evidence record carries the stored path as `uri` and ends with a recovery pointer (path and the full-output SHA-256), and `ccon gate-output` prints it back only after the stored streams verify against their own digests and the evidence digest. How the evidence shows the output is a per-run choice, `ccon run --tool-output bounded|summary`: `bounded` (default) is the first 8,000 characters; `summary` is an explicit opt-in to a deterministic summary made only of the output's own lines (head, tail, count lines, failure blocks, error-looking lines; repeats collapsed with a count; everything left out counted; nothing rewritten). | D-075 | The merge decision fails closed.
